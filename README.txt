致理．心夥伴－活動報名系統 V11.21.11 正式整合版
更新時間：2026/09/16 01:22（台灣時間）

一、檔案內容
1. Code.gs：Google Apps Script 後端完整檔案
2. index.html：GitHub Pages 前端主頁
3. app.js：GitHub Pages 前端程式
4. app-custom.css：GitHub Pages 前端樣式
5. verify_*.js：本機驗證程式，不需上傳 GitHub 或 GAS

二、建議更新順序
1. 先以 Code.gs 全部取代 GAS 專案現有檔案，儲存後部署「新版本」。
2. 確認 GAS 網頁應用程式網址仍與 app.js 最上方 GAS_API_URL 一致。
3. 再將 index.html、app.js、app-custom.css 上傳 GitHub，覆蓋同名檔案。
4. GitHub Pages 部署完成後，以無痕視窗確認導覽列顯示 V11.21.11。

重要：本版新增 getAdminDataPage、getAdminEventParticipants、recordLogin 端點，
務必先部署 Code.gs，再更新 GitHub 前端。後端仍保留舊版端點相容性。

三、V11.21.11 主要修正
- 手機版後台活動清單改為逐筆卡片，不再套用桌機 1100px 固定欄表格。
- 手機活動卡完整顯示分類、形式、活動名稱、承辦人、場次、公開狀態與操作按鈕。
- 手機頂部固定為四個主要功能 ICON 平均排列，登入身分以後台 ICON 狀態呈現。
- 手機登出按鈕獨立放在系統名稱列，不再占用主要功能的四欄位置。
- 手機篩選器及「重整／新增活動」按鈕限制於畫面寬度，不再向右溢出。
- 桌機後台表格與 V11.21.10 的載入、分頁及管理功能維持不變。

四、V11.21.10 延續功能
- 後台活動清單預設只顯示「即將到來」，可切換「已過期活動」或「全部活動」。
- 三種範圍都由後端篩選、排序及分頁，每次固定載入 5 項，換頁才讀取下一批。
- 即將到來活動依最近場次優先；已過期活動依最近結束時間優先；全部活動先排未來再排過期。
- 後台清單初次不讀取完整報名名單；點名單或通知功能時才按活動讀取學生資料。
- 學生報名專區初始分頁直接讀取必要活動與統計，不再先建立整包公開資料。
- 登入成功後才另行背景寫入登入紀錄，避免紀錄寫入延長登入等待。
- 同一分頁短時間重整可復原 STAFF 工作階段，不必立刻再次輸入帳密。
- STAFF 登入時清除學生查詢及報名暫存狀態，切回前台不沿用先前學生身分。
- 新增報名的動態紀錄改顯示活動名稱；舊活動 ID 紀錄可解析時也轉為名稱顯示。
- 延續 V11.21.9 的按需載入、逾時狀態確認、表單保留與防重複送出。

五、保留不變
- 不新增或更動任何試算表欄位。
- 容量、一對一、多場次、系列活動與衝堂判斷規則不變。
- LINE 通知及 Google 行事曆邏輯不變。
- V11.21.8 的未勾場次確認、防重複報名與手機版報名說明收合均保留。
- 不新增「最多選三門」的文字或限制提示。

六、上線後必要測試
1. 無痕開啟報名專區，確認近期活動先顯示且可按「載入更多活動」。
2. 測試多項報名，其中一項完全未勾場次，確認返回時不送出、放棄時只送已選活動。
3. 登入後應立即看見快速入口；載入清單時預設為「即將到來」且每頁最多 5 項。
4. 分別切換「已過期活動／全部活動」與頁次，確認項目及排序正確。
5. 點報名名單、LINE 通知及編輯功能，確認按需載入後可正常操作。
6. 以學生身分查詢後登入 STAFF，確認前台不再保留該學生的已報名狀態。
7. 新增測試報名後查看動態紀錄，確認顯示學生姓名與活動名稱，而非活動 ID。
8. 確認帳密錯誤、網路中斷與 Google 回應逾時仍顯示不同訊息。
