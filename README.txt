致理．心夥伴－活動報名系統 V11.21.17 正式整合版
更新時間：2026/09/18 22:30（台灣時間）

一、檔案內容
1. Code.gs：Google Apps Script 後端完整檔案
2. index.html：GitHub Pages 前端主頁
3. app.js：GitHub Pages 前端程式
4. app-custom.css：GitHub Pages 前端樣式
5. app-icon.svg：A 版「心夥伴」主圖示

二、建議更新順序
1. 先以 Code.gs 全部取代 GAS 專案現有檔案，儲存後部署「新版本」。
2. 確認 GAS 網頁應用程式網址仍與 app.js 最上方 GAS_API_URL 一致。
3. 再將 index.html、app.js、app-custom.css 及上述全部圖示檔上傳 GitHub，覆蓋同名檔案。
4. GitHub Pages 部署完成後，以無痕視窗確認導覽列顯示 V11.21.17。

重要：本版沿用 getAdminRegistrationSaveStatus 端點，
務必先部署 Code.gs，再更新 GitHub 前端。後端仍保留舊版端點相容性。

三、V11.21.17 主要修正

1. 完整活動月曆沿用既有活動索引及匿名報名統計快取，不再重複掃描 Events、Registrations、Students。
2. 匿名名額統計快取由 20 秒調整為 60 秒；所有報名異動仍會立即清除統計快取，送出報名仍直接讀取最新資料。
3. 前台首次只讀取活動及名額；個管老師名單延後到開啟報名或查詢視窗時才載入。
4. 公開活動第一頁會在瀏覽器保留 5 分鐘；再次開啟時先顯示最近資料，再於背景確認最新內容。
5. STAFF 身分驗證結果短效快取 60 秒；承辦人選項快取 5 分鐘，減少後台每個操作重讀 Admins。
6. API 回傳伺服器處理時間，前端會在開發者主控台記錄超過 1 秒的總時間、伺服器時間及推估網路時間。
7. 不更動試算表欄位、報名、容量、衝堂、LINE 與 Google 行事曆邏輯。

四、V11.21.16 延續功能

1. 活動月曆使用獨立的完整公開活動資料，不與後台目前頁面的活動陣列共用。
2. 後台的範圍、年度、分類、承辦人、關鍵字篩選及分頁，不影響活動月曆顯示內容。
3. 月曆剩餘名額使用獨立統計資料，不受後台目前頁面的報名統計影響。
4. 從月曆點選活動前往報名時，即使活動不在報名專區第一批資料內，仍可正確顯示。

五、V11.21.15 延續功能

1. 手機版活動月曆移除「日曆說明」，僅保留「活動月曆」與簡短提示，增加下方月曆可視空間。
2. 手機版報名專區移除「報名說明」與 1／2／3 步驟；桌機版仍保留流程步驟。
3. 單一場次活動的剩餘名額移到日期與時間旁，位置與多場次活動一致；已額滿也在相同位置顯示。
4. 前台、登入及後台資料讀取加入分階段狀態文字；Google 回應較慢時會提示勿重複點擊，載入失敗仍保留登入狀態與快速新增入口。
5. 動態紀錄由後端排除「登入系統」紀錄，只回傳最新 50 筆操作紀錄；前端另有相同限制作為保護。
6. 不更動試算表欄位、容量、衝堂、LINE 與 Google 行事曆邏輯。

六、V11.21.14 延續功能

1. 將頁首、後台登入畫面與無活動圖片預設圖示統一改為 A 版「心夥伴」圖示。
2. 補齊瀏覽器分頁、iPhone 主畫面與網頁應用程式所需的完整圖示檔。
3. 手機版活動月曆改為白底精簡卡片，完整說明預設收合，展開後才顯示分類與操作提示。
4. 「回到今天」移至月份控制列；手機以圖示呈現，桌機保留完整文字。
5. 月曆、報名、資料欄位、容量、衝堂、LINE 與 Google 行事曆邏輯均未更動。

七、V11.21.13 延續功能

1. 公開活動與後台活動清單改用 5 分鐘活動索引快取；快取命中時，翻頁、搜尋與篩選不再重複讀取完整 Events。
2. 報名人數與一對一占用時段改用 20 秒短效統計快取，且只保存 EventId 與場次 JSON，不保存學生個資。
3. 報名異動只清除統計快取，保留活動索引；活動異動才清除並重建活動索引。
4. 公開活動索引先套用欄位白名單；未公開活動只存在需要後台權限的伺服器端索引。
5. 送出報名時仍直接讀取最新試算表，原有容量、衝堂、一對一、LINE 與 Google 行事曆邏輯不變。

八、V11.21.12 延續功能
- 「個管老師手動新增報名」改為深藍標題列、白字及黃色分隔線，並固定表單文字為高對比深色。
- 學號驗證改為在 Students 學號欄精確尋找，只讀取命中的單筆必要資料，不再載入整張學生表。
- 驗證超過 5 秒會明確顯示 Google 回應較慢，最長等待 15 秒後顯示可辨識的逾時訊息。
- 手動新增送出時鎖定按鈕，並使用固定 RegistrationId 防止重複寫入。
- 後端一回報成功便立即關閉新增視窗及停止全畫面轉圈，清單與名單改在背景依序同步。
- 送出逾時時會查核 RegistrationId 是否已寫入，避免將已成功新增誤判為失敗。
- 背景同步失敗只提示重新整理，不會把已成功寫入的報名顯示成新增失敗。

九、V11.21.11 延續功能
- 手機版後台活動清單改為逐筆卡片，不再套用桌機 1100px 固定欄表格。
- 手機活動卡完整顯示分類、形式、活動名稱、承辦人、場次、公開狀態與操作按鈕。
- 手機頂部固定為四個主要功能 ICON 平均排列，登入身分以後台 ICON 狀態呈現。
- 手機登出按鈕獨立放在系統名稱列，不再占用主要功能的四欄位置。
- 手機篩選器及「重整／新增活動」按鈕限制於畫面寬度，不再向右溢出。
- 桌機後台表格與 V11.21.10 的載入、分頁及管理功能維持不變。

十、V11.21.10 延續功能
- 後台活動清單預設只顯示「即將到來」，可切換「已過期活動」或「全部活動」。
- 三種範圍都由後端篩選、排序及分頁，每次固定載入 5 項，換頁才讀取下一批。
- 即將到來活動依最近場次優先；已過期活動依最近結束時間優先；全部活動先排未來再排過期。
- 後台清單初次不讀取完整報名名單；點名單或通知功能時才按活動讀取學生資料。
- 學生報名專區初始分頁直接讀取必要活動與統計，不再先建立整包公開資料。
- 登入成功後才另行背景寫入登入紀錄，避免紀錄寫入延長登入等待。
- 同一分頁短時間重整可復原 STAFF 工作階段，不必立刻再次輸入帳密。
- STAFF 登入時清除學生查詢及報名暫存狀態，切回前台不沿用先前學生身分。
- 新增報名的動態紀錄改顯示活動名稱；舊活動 ID 紀錄可解析時也轉為名稱顯示。
- 延續 V11.21.9 的按需載入、逾時狀態確認、表單保留與防重複送出。

十一、保留不變
- 不新增或更動任何試算表欄位。
- 容量、一對一、多場次、系列活動與衝堂判斷規則不變。
- LINE 通知及 Google 行事曆邏輯不變。
- V11.21.8 的未勾場次確認及防重複報名均保留；本版依需求移除手機版報名說明。
- 不新增「最多選三門」的文字或限制提示。

十二、上線後必要測試
1. 無痕開啟報名專區，確認近期活動先顯示且可按「載入更多活動」。
2. 測試多項報名，其中一項完全未勾場次，確認返回時不送出、放棄時只送已選活動。
3. 登入後應立即看見快速入口；載入清單時預設為「即將到來」且每頁最多 5 項。
4. 分別切換「已過期活動／全部活動」與頁次，確認項目及排序正確。
5. 在後台套用分類、承辦人、年度、關鍵字篩選並切換頁次後開啟活動月曆，確認所有公開活動仍完整顯示。
6. 點報名名單、LINE 通知及編輯功能，確認按需載入後可正常操作。
7. 以學生身分查詢後登入 STAFF，確認前台不再保留該學生的已報名狀態。
8. 新增測試報名後查看動態紀錄，確認顯示學生姓名與活動名稱、只列最新 50 筆且不顯示登入紀錄。
9. 確認帳密錯誤、網路中斷與 Google 回應逾時仍顯示不同訊息。
10. 手機開啟活動月曆及報名專區，確認兩頁均未顯示說明區塊，且「回到今天」仍位於月份列。
11. 確認頁首、後台登入畫面及瀏覽器分頁皆顯示新版心夥伴圖示。
